# events-v1

The submissions that are not moves.

Frozen. These strings are in games already, or they will be, and a reader in ten
years has only this document.

---

## 1. Why a string and not a function

The contract sees four or five characters and forms no opinion about them. That
is the whole filter.

So a resignation is not a new contract function, a new argument, or a flag. It is
a string that happens not to be a move, and replay is where it acquires meaning.

Adding `resign` as a contract function would mean the contract knew that games
can be resigned, which is a chess opinion, and the first one is the expensive
one. It would also mean that adding a new kind of event later required a new
contract, and every game opened under the old one could never use it.

---

## 2. The strings

| string | meaning |
|---|---|
| `resgn` | the sender resigns; the other side wins |
| `draw?` | the sender offers a draw |
| `draw!` | the sender accepts the offer standing against them |

All three are five characters, so all three pass the contract's length filter.
That is not a coincidence; it is a requirement, and a test asserts it.

**Case sensitive.** UCI move parsing is lenient about case, because people type
moves into wallets by hand. A control string is generated by the board and never
typed, so one exact spelling means there is nothing to argue about. `RESGN` is
not a resignation; it is a malformed submission.

### They cannot collide with a move

A UCI move is two square names and an optional promotion letter. `resgn` fails
because `re` is not a square (file `r` is out of range); `draw?` fails because
`dr` is not a square. A test asserts that no reserved string ever parses as a
move, in any position.

---

## 3. Who may send one

A control event is attributed to a side by the rule set:

- sender equals `rules.white` → White
- otherwise sender equals `rules.black` → Black
- otherwise → **rejected**, reason `not-a-player`

Only a bound side can resign or agree a draw. On an open board where anyone may
play either colour there is nobody who owns the game, so there is nobody who can
end it. That is the honest answer, not a gap.

White is checked first. If one principal somehow holds both sides the result is
White, deterministically.

---

## 4. What applies and what does not

| rule | applies to a control event? |
|---|---|
| `allow` list | **yes** — it says who may take part at all |
| bound side | **yes** — via the attribution above |
| `cooldown` | **no** |
| `noConsecutive` | **no** |
| whose turn it is | **no** |

Cooldown and no-consecutive pace the **moves** in a game. Applying them to a
concession would mean a player could be prevented from conceding, which is not a
rule anybody agreed to and would make a game unfinishable.

A player may resign when it is not their turn. Conceding is not a move.

---

## 5. Draw offers

At most **one** offer stands at a time.

- `draw?` while any offer is standing is rejected, reason `offer-pending`. Two
  live offers would make "which one did this accept" a question the log cannot
  answer.
- `draw!` requires an offer **from the other side**. Accepting your own offer is
  not agreement: rejected, reason `no-offer`.
- `draw!` with nothing standing is rejected, reason `no-offer`.
- **Any accepted move clears a standing offer.** This is the FIDE reading — an
  offer lapses when the opponent moves — expressed as a rule that needs no clock.

An accepted `draw!` ends the game: result `1/2-1/2`, termination `agreement`.

---

## 6. Resignation

An accepted `resgn` ends the game at once.

| sender's side | result |
|---|---|
| White | `0-1` |
| Black | `1-0` |

## 7. `events-none`, and the games that came first

Three X Chess contracts were deployed before any of this existed. In their
games no string meant anything but a move, and `resgn` was five characters that
replay skipped as malformed.

That reading is named: **`events-none`**. Replay obeys the events protocol a
game committed to, so those games keep the results they had.

This is not a formality. A legacy Scholar's Mate with `resgn` at sequence 2
reads as **1-0 by checkmate** under `events-none` and **0-1 by resignation**
under `events-v1`. Opposite winners, from identical bytes. See ADR-0007 and
`tests/legacy`.

## 8. Adding an event later

A new control string is `events-v2`. Games commit to their events protocol in
their rules hash, so a game opened under `events-v1` is replayed under
`events-v1` forever, and a string that means something new in v2 remains a
malformed submission in a v1 game.

A reader that meets an events protocol it does not implement **refuses the game**
rather than falling back to its own. Guessing would produce a position no other
reader agrees with.

**The core contract does not need to change**, and must not. It does not know
these strings exist.
