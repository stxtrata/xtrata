XTRATA · BIP-110 & the future of on-chain media

What BIP-110 means for on-chain media — honestly

The short version: BIP-110 is a proposed Bitcoin rule change that would make storing data on Bitcoin L1 much harder: data pushes capped at 256 bytes, and the script trick behind today's Ordinals envelope disabled. It is a proposal, not an active rule — and nothing already inscribed is affected either way. Your existing inscriptions live in blocks that are permanent history.

Ordinals aren't dying — they're adapting

The ord developers have already drafted a replacement envelope that works within BIP-110's limits: data split into ≤256-byte pushes that are immediately dropped from the stack (ord PR #4545). Even the BIP-110 text concedes that data can't be stopped entirely — only made harder and more expensive. That's the real question this page answers: how much more expensive?

Where Xtrata stands

We think Bitcoin Core's instinct is defensible: L1 is for money. That's exactly why Xtrata exists — full media files, recursive references and composable records on a layer built for them, with every transaction still anchored to Bitcoin's finality through Stacks. No 256-byte chunks, no governance risk to your use case, and costs measured in cents.

And because we come from the Ordinals world ourselves (Xtrata's founder built Audionals on Bitcoin L1), we're keeping the L1 door open too: if BIP-110 activates, our chunking-and-batching pipeline — the same tech behind Xtrata's large-file inscriptions — will support the new ord envelope, so inscribing to Bitcoin stays painless for those who want it. Either layer. Your choice. Permanent either way.

Does my existing Ordinals work disappear?

No. Consensus changes constrain new transactions only. Everything already inscribed is inside blocks protected by all the proof-of-work mined since — archival nodes carry it forever, and any new node syncing the chain verifies it byte-for-byte. The realistic long-term risk isn't deletion; it's tooling: fewer indexers and viewers being maintained if inscribing declines. Preserving access infrastructure is precisely the layer Xtrata builds — including Forever Twins, permanent counterparts for existing collections.
