## What changed in the harness

**Posted work is now archived properly.** `comms:record` writes three things
rather than one: the index line, the full text and the image actually used in
`archive/<date>.json`, and a `posted` mark in the queue. The board reads posted
state from the journal at build time, so it survives a different browser and a
different machine. It used to be a localStorage tick, which meant the board
could not actually answer "have we posted this" anywhere except the laptop that
ticked it.

**The archive section reads `archive/`, not the current queue.** Posted drafts
stop being carried forward, so a queue-only archive would be empty every
morning, which is exactly when knowing what went out yesterday matters most.
It shows the last 14 days grouped by day, with no buttons at all, because
anything actionable in an archive is a way to post the same thing twice.

**Copying an image marks it used.** That is what the action means in practice.
Marking happens only on a successful clipboard write, so a blocked copy never
records a picture that never reached the post, and the badge is the undo. Picks
are a list rather than a single value, because X takes up to four images and a
wrong guess here silently mis-records what went out.

**Imagery is no longer committed.** `assets/` and every image under `comms/`
are gitignored on Jim's instruction. Consequence worth knowing: after a fresh
clone the image paths in old queues will not resolve, and the board renders a
red warning rather than pretending. The archive still records which image was
used by path, which is the part worth keeping. A capture is supposed to show
what the page looked like today, so restoring an old one from a clone would be
wrong anyway.
