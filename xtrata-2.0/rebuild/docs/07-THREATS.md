# Threat Model — Collections & Drops v3

Trust boundary: the blockchain and the approved contract set are authoritative. Browser storage, manifests, and indexers are caches. The relayer is semi-trusted (can censor/delay, must not be able to steal or misdirect).

| # | Threat | Attack | Mitigation | Where enforced |
|---|---|---|---|---|
| 1 | Supply oversubscription | Many concurrent sessions racing the last slots | Reservation increments `reserved-count` atomically before any other effect; `minted + reserved ≤ max` asserted at reserve; Stacks serializes txs, so no TOCTOU on-chain | collection `reserve`/`ensure-session` |
| 2 | Session hijacking | Third party seals/cancels another wallet's session | Sessions keyed `{owner, hash}`; all mutating paths require `tx-sender == owner` except permissionless expiry release (which only frees, never mints) | collection session guards |
| 3 | Fake collection membership | Passing foreign token-ids as collection items | Membership exists only via `Items` written at seal by the contract itself; Drops read membership from the collection, never from caller input | collection `Items`; drops inventory resolution |
| 4 | Duplicate/stolen inventory | Same item added to two drops; unminted item added | `Assignments` one-row-per-index, written only by `drops-authority` (contract-caller check); `assign-to-drop` requires minted + unassigned; range assignment is atomic | collection assignment ledger |
| 5 | Double claims | Same item claimed twice; same wallet over-claiming | `ItemClaimed{drop,index}` set-once; `WalletClaims` counter vs per-wallet limit; claim reservation decremented on settle; escrow NFT can only transfer once anyway | drops claim path |
| 6 | Sponsor draining | Grinding claims to burn budget; fee inflation | On-chain: `claim-fee ≤ budget-remaining` and `≤ claim-fee-cap`, sponsor-only. Off-chain: relayer rate limits (per-wallet + per-origin), float floor, MAX_UNSETTLED, decodes signed tx before spending anything | drops + relayer |
| 7 | Signature replay | Reusing a claim attestation elsewhere/later | Signature payload binds drop-id, claimer (=tx-sender), collection, contract principal, chain-id, expires-at; consumed rows recorded | drops `verify-attestation` |
| 8 | Claim front-running | Observing a mempool claim and stealing the item | Claims bind `tx-sender`; allocation resolves at execution, not from caller-chosen index (public modes); for explicit-index claims the reservation locks the index to the claimer first | drops reservation + allocation |
| 9 | Allocation manipulation | Miner/claimer biasing "random" allocation | Randomized mode documented as cosmetic pseudo-randomness (id-header-hash salt); anything value-differentiated must use deterministic or reveal-later ordering, stated in Builder UI | drops docs + UI copy |
| 10 | Malicious metadata | Script injection via names/URIs rendered in UI | Contract stores bounded ASCII; UI escapes all chain-derived strings; manifests validated against JSON Schema before render | client + UI |
| 11 | Abandoned reservations (griefing) | Locking supply with reservations never completed | `reservation-expiry-blocks`; **permissionless** `release-expired-reservation`; index returns to free-list; same for drop claim reservations | both contracts |
| 12 | Stale indexer data | UI acting on cached/incorrect state | Every write path pre-flights with read-only calls to the contracts; ingestion engine reconciles from chain before resuming; indexer used only for display | client engine |
| 13 | Network mismatch | Testnet artifacts pointed at mainnet or vice versa | Principal-prefix guards (SP/SM vs ST/SN) in client + canary; chain-id inside signatures; deploy canary verifies connected network first | client, relayer, canary |
| 14 | Compromised admin | One key pauses/steals | Role separation (owner / operator / finance); two-step ownership transfer; finalize freezes config; funds only ever flow per fixed splits — no arbitrary-withdraw function exists | collection roles |
| 15 | Incorrect dependency addresses | Template substitutes wrong core/drops principal | Compile-time constants + canary source-parity (SHA-256 of deployed vs local source) + interface probe + read-only round-trip before any state-changing canary step | canary |
| 16 | Partial deployment | Drops live without verified collection path, or relayer pointed at unverified contract | Canary enforces dependency order with per-stage gates; app config activation is the explicit final stage; relayer allowlist updated only after on-chain verification | canary process |
| 17 | Relayer request forgery | Body claims a different drop/contract than the signed tx | Signed transaction is the sole source of truth: relayer decodes contract, function, args, post-conditions and rejects on any mismatch; PCs must allow exactly one NFT movement | relayer |
| 18 | Hot-wallet nonce races | Concurrent sponsorships double-spend a nonce | Single-writer nonce authority (Durable Object) + atomic D1 job leases (`UPDATE … WHERE state=…`, proceed iff 1 row) | relayer |
| 19 | Successful-broadcast-unseen | Client retries a tx that actually landed | Idempotency by content hash (`get-id-by-hash`, `HashIndex`, session state) — retry is a no-op or resumes; relayer checks txid-known before rebroadcast | client engine + relayer |
| 20 | Unclaimed-inventory theft | Non-creator sweeping ended drops | Recovery paths gated to drop creator (or sponsor for fee settlement only); unassign requires matching drop-id via authority | drops recovery |
